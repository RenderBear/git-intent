# Conflict resolution

Compose both sides against the selected domains, accepted contracts, referenced architecture,
and the requested outcome. Never choose a side merely because Git calls it `ours` or `theirs`.

Confirm an actual unmerged index, identify the Git operation, inspect base and both stages, then
classify the conflict as adjacent, compatible overlap, structural relocation, or semantic
contradiction. Path overlap alone is not contradiction.

For semantic conflict, recompile the brief and retrieve only relevant defining material. Preserve
both compatible properties. If accepted meanings cannot coexist, use the consequential-resolution
protocol. Run all affected verifiers and review architecture before continuing.

Write only when the invoking task authorizes conflict resolution. Do not commit, push, alter
unrelated worktrees, or stage unrelated files.
