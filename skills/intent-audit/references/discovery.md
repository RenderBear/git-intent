# Scoped discovery

Adoption is demand-driven. Missing route coverage is an observed posture, not a failure.

Seeding promotes selected derived boundaries into durable intent. It does not create a repository
inventory.

## Fresh repository

1. Brief the first goal. If the user did not ask to establish intent and no critical shared boundary is needed, continue observed.
2. Extract the smallest charter supported by the request: macro goal and non-goals, planned critical interfaces or protocols, and communication or integration constraints.
3. Run `scripts/audit-support.sh scope --paths <planned-paths...>`.
4. Propose minimal routes to accepted sources and contracts only where reliance and executable verification already exist.
5. Emit a candidate packet. After authority resolution, `intent-record` writes and validates the accepted rows and executes new verifiers. The accepted intent may share the repository's root landing.
6. Recompile the brief before implementation.

## Mature repository

1. Brief the current goal. If no route matches, continue observed.
2. If the touched boundary is critical or recurrent, run discovery on the touched paths.
3. Inspect only that boundary, immediate consumers, stable accepted sources, and executable checks.
4. Emit the smallest justified route and contract candidates for authority resolution.
5. Record accepted intent before dependent work only if it must govern that work. Otherwise make a non-blocking suggestion after landing.
6. After `intent-record` writes accepted rows, recompile the brief.

Discovery never writes.

## Candidate rules

A route candidate needs stable anchors and at least one inspectable governing pointer. A contract candidate additionally needs a durable relied-on assertion, accepted authority, identifiable surfaces, and executable verification.

Code and history may reveal structure and reliance. They do not make behavior normative.

For a repository-wide audit, read [full-audit.md](full-audit.md). It requires an explicit human
request and proceeds in bounded batches.

Recurrence may surface a post-landing suggestion. It never blocks or amends the landing that revealed it.
